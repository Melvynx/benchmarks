# Benchmark Compare UI Audit: Baseline

## Audit health score

| Dimension | Score | Key finding |
| --- | ---: | --- |
| Accessibility | 2/4 | Several icon controls are below 40x40, duplicate transcript activity IDs appear in multi-panel views, and selection-limit feedback is missing. |
| Performance | 3/4 | Rendering is generally lean, but repeated array lookups and `Intl.NumberFormat` construction add avoidable work. |
| Responsive design | 2/4 | The mobile toolbar collides with the title and exposes controls that are irrelevant without a selection. |
| Theming | 4/4 | The app consistently uses the existing dark neutral and amber token system. |
| Anti-patterns | 2/4 | The result catalog repeats bordered cards and the error page uses decorative gradients, blur, and a heavy shadow. |
| **Total** | **13/20** | **Acceptable, significant work needed** |

## Anti-pattern verdict

The workbench itself is restrained, but the catalog reads as a repeated card grid and the error state looks like a generated SaaS error template. The generated apps still remain visually dominant once selected, which is the right product priority.

## Confirmed findings

### P1: Mobile command bar collision

- **Location:** `src/routes/index.tsx`, workbench header
- **Impact:** At 390px the title truncates into two unreadable fragments while seven controls consume the row.
- **Standard:** WCAG 1.4.10 Reflow
- **Action:** Make the command bar state-aware, hide irrelevant control groups, and give mobile a compact title/count.

### P1: Touch targets are too small

- **Location:** Shared icon buttons and comparison panel actions
- **Impact:** 28px controls are difficult to hit on touch screens and at increased zoom.
- **Standard:** WCAG 2.5.8 Target Size (Minimum)
- **Action:** Use at least 40px targets, 44px on coarse pointers, while preserving dense visual icon sizing.

### P1: Duplicate transcript activity IDs

- **Location:** `src/components/transcript-phase-chart.tsx`
- **Impact:** Two evidence panels create the same `aria-labelledby` target, so assistive technology can resolve the wrong heading.
- **Standard:** WCAG 4.1.2 Name, Role, Value
- **Action:** Scope the heading ID to the benchmark result.

### P1: Selection limit has no feedback

- **Location:** `toggleResult` in `src/routes/index.tsx`
- **Impact:** Clicking a fifth result silently does nothing, which looks broken.
- **Action:** Disable unselected rows at the limit and explain that one selected result must be removed.

### P2: Catalog is visually repetitive

- **Location:** Result list in `src/routes/index.tsx`
- **Impact:** Repeated bordered cards slow scanning and consume vertical space.
- **Action:** Convert the catalog to compact list rows with separators and a single selected state.

### P2: Irrelevant controls remain visible

- **Location:** Workbench toolbar
- **Impact:** Layout, scroll, reload, copy, and clear actions compete with the empty state or single-result view.
- **Action:** Reveal controls only when their prerequisites exist.

### P2: Error page is over-styled

- **Location:** `src/components/app-error.tsx`
- **Impact:** Decorative grid, radial glow, backdrop blur, and heavy shadow conflict with the quiet product shell.
- **Action:** Reduce to one clear recovery surface with concise copy and accessible details.

### P2: Avoidable repeated computation

- **Location:** `src/routes/index.tsx`, `src/components/evidence-overview.tsx`
- **Impact:** Repeated `includes` scans and formatter construction add work as the catalog grows.
- **Action:** Memoize lookup sets and hoist number formatters.

## Positive findings

- The URL remains the source of truth for selection, filters, and layout.
- Generated apps remain the primary visual content.
- Filters are labeled and use shared shadcn/ui primitives.
- Focus states and semantic button roles are already present.
- Overview uses progressive disclosure well and avoids the old wall of missing metadata.
- Dark theme tokens and phase colors are consistent.
