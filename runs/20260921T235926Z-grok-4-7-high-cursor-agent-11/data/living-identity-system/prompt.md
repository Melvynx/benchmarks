# Living Identity System

## Mission

Create a single self-contained browser experience that invents and expresses a complete living visual identity for this fictional cultural event:

- Name: **NOCTURNE**
- Description: **Festival of Impossible Light**
- Date: **18 October**
- Doors: **19:30**
- Venue: **Atlas Observatory**
- Artists: **Mira Vale · Glass Choir · Static Bloom**
- Creative tension: **ceremonial · electric · intimate**

The result must feel authored, surprising, and unmistakably coherent. Do not build a conventional event landing page or a collection of generic cards. Invent a visual language, then prove that it can survive across static composition, motion, and direct interaction.

## Three required expressions

Build all three expressions inside the same experience. Provide a clear way to switch between them.

### 1. Poster

Create a carefully composed 4:5 festival poster using the supplied event content. It must work as a complete artwork, not as a screenshot of a website. Typography, hierarchy, negative space, texture, geometry, illustration, and information placement should feel intentional.

### 2. Motion

Create a replayable 12-second kinetic title sequence for the same identity. It must have a real beginning, development, climax, and resolution. Animate typography and the visual system with purposeful rhythm rather than continuously moving everything. Include Play/Pause, Replay, and a scrubber or visible progress control.

### 3. Instrument

Create an interactive generative scene derived from the same identity. Pointer movement, dragging, touch, or keyboard input must visibly transform the composition. The interaction should feel expressive and satisfying, not like a settings panel controlling decorative particles.

The three expressions must share a recognizable conceptual system while using genuinely different compositions. Simple palette swaps or the same layout in three containers are not enough.

## Art direction

Choose the visual concept, typography strategy, palette, rendering medium, motifs, transitions, and interaction behavior yourself. Take a clear creative position. Avoid familiar startup aesthetics, generic dark dashboards, glass cards, decorative gradient blobs, and interchangeable component-library layouts unless you radically transform them into something specific to this identity.

Use only graphics generated by the application itself. You may use HTML, CSS, SVG, Canvas 2D, or WebGL, but do not load external images, fonts, videos, libraries, APIs, or other network assets. System fonts are allowed.

## Experience requirements

- The current expression must fill the experience and remain visually dominant.
- Switching expressions must feel like entering another manifestation of the same identity.
- Preserve every exact piece of supplied event content somewhere legible in the experience.
- Make the Poster composition readable at a 4:5 aspect ratio and present it elegantly inside wider screens.
- Make the Motion timeline deterministic and independent of display refresh rate.
- Make the Instrument respond immediately to pointer and touch input.
- Include a seed control or a small set of seed variations that remain recognizably part of the same identity family.
- Handle desktop, narrow mobile, high-DPI displays, keyboard focus, and `prefers-reduced-motion` gracefully.
- Keep the console free of avoidable errors.

## Deterministic interface

Expose `window.__LIVING_IDENTITY__` with callable methods:

- `reset(seed)` — restore the entire experience with the supplied integer seed;
- `setMode(name)` — accept `poster`, `motion`, or `instrument`;
- `seek(milliseconds)` — place the Motion sequence at an exact time from 0 through 12000;
- `snapshot()` — return a JSON-safe summary containing seed, mode, motion time, play state, and the meaningful state of the interactive composition;
- `runSelfTest()` — exercise the real state functions and return `{ passed, tests }`, with a name, boolean pass value, and short detail for every check.

At minimum, the self-test must verify deterministic reset, all three modes, exact Motion seeking, the 12-second timeline boundary, and finite numeric state after interaction.

## Technical constraints

- Create exactly one complete `index.html` file.
- Put all markup, styles, rendering, animation, interaction, and logic in that file.
- The file must open directly in a modern browser without a server or build step.
- Do not use external dependencies or network requests.
- Use a seeded pseudo-random generator for every identity-affecting variation.
- Cap animation deltas and do not let tab suspension corrupt the timeline.
- Every visible control must work.

## Quality bar

The finished result should feel like a renowned independent design studio, motion designer, creative coder, and interaction designer built one small but complete cultural identity together. It should reward close inspection, but the concept and difference between the three expressions should be obvious within fifteen seconds.

Build the experience directly. Make the creative decisions yourself, run one concise validation pass, fix blocking failures, and keep the final response brief.

Work only inside the current working directory. Do not edit files outside the current working directory.

Use pnpm exclusively if dependency installation or package scripts are needed. Do not use npm.
Set the browser title and the primary visible title to your model name, using only identity information already available to you. Add nothing else to either title.
Run the relevant checks yourself. Do not edit files outside the current working directory.
