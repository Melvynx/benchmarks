The timezone overlap checker is built and running: `pnpm dev` serves it on **http://localhost:9229** (strict port). The browser title and the page heading are both **Claude Opus 5.5**.

**Verification:** the typecheck is clean, the production build succeeds, and 15 unit tests pass. I also drove the app in a headless browser at desktop and mobile sizes. Everything below worked there:
- **Defaults on a fresh visit:** San Francisco, Denpasar and Geneva, Meeting Mode, awake 7am–11pm, 12h format. The summary shows 2 hours of overlap (7am — 8am and 10pm — 11pm, San Francisco time), and the "Green cells = everyone awake" hint is at the bottom.
- **Cities:** adding by keyboard ("nep" + Enter adds Kathmandu) and by country ("japan" adds Tokyo). A city already on the list no longer appears in the search.
- **Reference city:** clicking Geneva made it the reference and moved it to the top.
- **Persistence:** the city list, mode and settings all came back after a refresh.
- **Math spot-checks by hand:**
  - Base Mode gave Kathmandu (UTC+5:45) 7am — 8pm of overlap with Geneva, which matches.
  - A night-shift window (10pm → 6am) with London as reference gave 22:00 — 02:00, shown as one range across midnight.
  - An impossible schedule showed the zero-overlap warning in both modes.
- **Mobile (390px wide):** cities become columns and hours become rows, with no horizontal page overflow.
- **Dark theme and 24h format:** both render correctly.

**Stack:** Vite + React 19 + TypeScript, styled with CSS Modules and no UI library.

- **Overlap and timezone logic** (`src/lib/schedule.ts`) is plain functions, separate from the React code. Offsets come from the browser's built-in timezone data for the current date, so daylight saving time and offsets like +5:30 or +5:45 are handled.
- **App state** is one reducer with typed actions (`src/state/`). It's saved to localStorage and checked on load, so bad or outdated saved data falls back to defaults.
- **Desktop and mobile** are two separate grid components (`DesktopGrid`, `MobileGrid`) that share one cell component (`HourCell`).

**Design choices I made:**
- Neighbouring hours in the same state join into one continuous pill, so the green overlap stands out as a solid block across the rows.
- Sleeping hours use a faint striped texture rather than just low contrast.
- A red "Now" line marks the exact current time, and a small weekday tag (e.g. "TUE") marks where each city's local day changes.
- Hovering an hour highlights that column in every city.
- The city search is keyboard-driven and grouped by region, with each city's current UTC offset. It ignores accents, so "sao" finds São Paulo.
- The catalog has 35 cities.
- Dark mode follows the system setting.

**Behaviours you might not expect:**
- If the wake and sleep hours are the same, I treat that as awake around the clock.
- A city with a half-hour offset counts as awake based on its local hour, so 6:30am is asleep with a 7am wake time.
- In Base Mode, the reference city's row lights up any hour where it overlaps with at least one other city.
- "Reset all" restores everything to defaults, including the city list, without asking first.

Separately, two connected services (chatcut and posthog) need authorization before their tools can be used. Authorize them through claude.ai connector settings, or with `/mcp` in an interactive session. This project didn't need either one.
